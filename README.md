# پورتفولیوی فرحناز اصغرپور

سایت ایستا و بدون مرحلهٔ build، دو‌زبانه و آمادهٔ میزبانی روی Vercel، Netlify، Cloudflare Pages یا GitHub Pages است. نسخهٔ فارسی در `/` و نسخهٔ انگلیسی در `/en/` قرار دارد.

## ساختار پروژه

```text
index.html                    صفحهٔ اصلی فارسی
en/index.html                 صفحهٔ اصلی انگلیسی
projects/radmehr/index.html   مطالعهٔ موردی رادمهر، فارسی
en/projects/radmehr/index.html مطالعهٔ موردی رادمهر، انگلیسی
css/style.css                 استایل‌های عمومی و سیستم رنگ
css/project-details.css       استایل صفحه‌های مطالعهٔ موردی
js/main.js                    تم، منو، کپی ایمیل (همهٔ صفحه‌ها)
js/gallery.js                 گالری تعاملی رادمهر (فقط صفحه‌های مطالعهٔ موردی)
js/theme-init.js              بازیابی تم پیش از نمایش صفحه
assets/images/radmehr/        تصویر شاخص، اسکرین‌شات‌های WebP و og-radmehr.jpg
assets/images/radmehr/gallery/thumbs/  بندانگشتی‌های سبک (۳۶۰px) برای فهرست گالری
```

> نام عکس‌های گالری عمداً عوض شده (`radmehr-NN-…`)؛ چون فایل‌های `assets/` با کش یک‌ساله سرو می‌شوند، نام تازه یعنی بازدیدکننده‌های قبلی هم عکس‌های جدید را می‌بینند. اگر بعداً عکسی را عوض کردید، نامش را هم عوض کنید.


متن هر صفحه مستقیماً داخل HTML همان زبان قرار دارد. صفحهٔ مطالعهٔ موردی رادمهر در `projects/radmehr/index.html` نگهداری می‌شود.

## گالری مطالعهٔ موردی رادمهر

- **چیدمان دسکتاپ (قاب حدود ۷۵۸×۴۷۴ و فهرست حدود ۳۴۴px):** قاب تصویر در چپ (نسبت ۱۶:۱۰، ستون‌ها ۱٫۷۲ به ۰٫۷۸) و فهرست عمودی تصاویر در راست. ارتفاع فهرست همیشه با ستون چپ برابر است و خودش اسکرول می‌خورد.
- **پر شدن قاب:** تصویر با `object-fit: cover` قاب را کامل پر می‌کند. اگر برش تصویر از حد مجاز بیشتر شود (بیش از ۲۵٪ از پایین برای تصویرهای بلند یا بیش از ۱۰٪ از کناره‌ها برای تصویرهای عریض)، تصویر کامل نمایش داده می‌شود و نسخهٔ محوشدهٔ خودش قاب را پر می‌کند؛ پس هیچ محتوایی بریده نمی‌شود. این حالت با `data-fit="cover"` یا `data-fit="contain"` روی هر اسلاید در HTML مشخص شده و هر وقت خواستید می‌توانید برای یک اسلاید عوضش کنید؛ برای تصویر جدید هم همین قانون را رعایت کنید.
- **نمای کامل:** دکمهٔ «نمای کامل» همان تصویر را بدون هیچ برشی در یک `<dialog>` بومی باز می‌کند (Esc، تله‌ی فوکوس و بازگشت فوکوس را خود مرورگر انجام می‌دهد).
- **پخش خودکار:** با انیمیشن CSS نوار پیشرفت هدایت می‌شود و پایان انیمیشن تصویر بعدی را نشان می‌دهد؛ بنابراین نوار و تصویر هرگز ناهماهنگ نمی‌شوند. پخش وقتی متوقف می‌شود که: کاربر مکث بزند، ماوس روی قاب باشد، فوکوس صفحه‌کلید داخل گالری باشد، گالری در دید نباشد، تب پنهان باشد یا نمای کامل باز باشد. با `prefers-reduced-motion` پخش خودکار اصلاً فعال نمی‌شود.
- **کنترل‌ها:** دکمه‌های قبلی/بعدی/مکث، کشیدن انگشت روی قاب (جهت در RTL برعکس است)، فلش‌های صفحه‌کلید (با جهت خواندن صفحه هماهنگ)، Home و End.
- **دسترس‌پذیری:** `role="region"` با `aria-roledescription="carousel"`، برچسب هر اسلاید، و یک ناحیهٔ `aria-live` که فقط وقتی کاربر خودش تصویر را عوض می‌کند خبر می‌دهد.
- **ریسپانسیو:** تا ۹۲۰px دو‌ستونه است؛ زیر آن ستون‌ها روی هم می‌روند و فهرست تصاویر افقی و لمسی می‌شود. برچسب دکمه‌ها در عرض‌های خیلی کم به آیکن تبدیل می‌شود.
- **سرعت:** ۱۳ تصویر کامل روی هم حدود ۵۶۵KB است (نسخهٔ PNG اصلی حدود ۶MB بود) و فهرست از بندانگشتی‌های ۳۶۰px (حدود ۱۱۰KB روی هم) استفاده می‌کند. فقط تصویر اول و بعدی بارگذاری می‌شوند؛ بقیه تنبل‌اند.
- **متن‌ها:** همهٔ برچسب‌ها داخل HTML هستند (`data-label-*`)، پس نسخهٔ فارسی و انگلیسی کد جاوااسکریپت مشترک دارند.

## فناوری و وابستگی‌ها

این پروژه از HTML5، CSS3 و JavaScript بومی استفاده می‌کند. برای گالری و تعامل‌های جدید هیچ jQuery، GSAP، Lenis، CDN یا کتابخانهٔ خارجی اضافه نشده است. حرکت‌ها و زمان‌بندی گالری با CSS (انیمیشن و `animationend`) مدیریت می‌شوند.

## قبل از انتشار

1. دامنهٔ نهایی را جایگزین `https://farahnaz-portfolio.vercel.app` کنید. این نشانی در فایل‌های HTML (canonical، hreflang، Open Graph و JSON-LD)، `sitemap.xml` و `robots.txt` استفاده شده است.
2. پیوند شبکه‌های اجتماعی را فقط پس از آماده‌شدن نشانی واقعی اضافه کنید.
3. نسخهٔ زندهٔ رادمهر و مسیر نمایش دمو را پس از انتشار نهایی بررسی کنید.
4. پس از انتشار، sitemap را در Google Search Console ثبت کنید و هدرهای امنیتی و سرعت را بررسی کنید.

## امنیت و میزبانی

- اسکریپت‌ها، استایل‌ها، فونت‌ها و تصاویر از دامنهٔ خود سایت بارگذاری می‌شوند.
- سیاست CSP در HTML و هدرهای میزبانی، اجرای اسکریپت را به `'self'` محدود می‌کند و به سرویس CDN شخص ثالث نیاز ندارد.
- `frame-ancestors` باید از طریق هدر HTTP در `vercel.json` یا `_headers` اعمال شود؛ متاتگ HTML برای این دستور کافی نیست.
- هدرهای امنیتی و تنظیمات کش فایل‌های ایستا را در `vercel.json` و `_headers` حفظ کنید.
